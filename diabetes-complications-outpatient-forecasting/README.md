# End-to-End Healthcare Data Engineering Framework
### Predictive Modelling for Type 2 Diabetes Complications & Outpatient Clinic Load Forecasting

A production-style, config-driven data platform that takes multi-source (synthetic,
non-PHI) patient records from raw ingestion all the way to (a) a calibrated model
predicting 12-month patient deterioration and (b) a 12-week outpatient visit-volume
forecast with cost-optimised staffing plans.

> **Data note:** All data is synthetically generated by the project's own
> `data_generator.py`. No real patient data or PHI is used anywhere.

---

## Highlights

- **Layered architecture** — independent `data_engineering`, `eda`, `modeling`,
  `forecasting` and `utils` packages, orchestrated by a single CLI.
- **Real data-engineering layer** — Pydantic-validated schemas, an ETL pipeline with
  data-quality reporting, NLP keyword extraction from clinical notes, a Parquet
  feature store, and an auto-generated data catalogue.
- **Credible ML** — four tuned classifiers, leakage control, isotonic calibration,
  a model registry and an inference API. Best model ROC-AUC **0.875** (not an
  inflated/leaky 0.99).
- **Forecasting + operations research** — Prophet+SARIMA ensemble demand forecast,
  resource scheduling with surge buffers, and a PuLP linear program for cost-optimal
  staffing, plus an HTML dashboard.
- **Engineering quality** — centralised YAML config, reproducible seeding, a pytest
  suite, `pyproject.toml` packaging, and a Makefile.

## Quick start

```bash
cd diabetes-complications-outpatient-forecasting

# 1. install dependencies
pip install -r requirements.txt          # or: make install

# 2. run the whole platform end to end
python main.py --pipeline full           # or: make all

# ...or run individual stages
python main.py --pipeline data_engineering   # make data
python main.py --pipeline eda                # make eda
python main.py --pipeline modeling           # make model
python main.py --pipeline forecasting        # make forecast

# 3. run tests
make test
```

Stages are independent but ordered: `data_engineering` must run first to populate the
feature store; `eda`, `modeling` and `forecasting` then consume it.

## Pipeline stages

### 1. Data engineering
Generates five raw sources (patients, labs, outpatient visits, clinical notes,
complications), validates them against Pydantic schemas, runs quality checks, cleans
and standardises the data, extracts NLP flags from notes, and builds:
- `data/feature_store/features.parquet` — 12,000 patients × 43 features
- `data/feature_store/weekly_demand.parquet` — 102 weeks (total + per clinic)
- `docs/data_catalog.json` — profile of all 13 datasets

### 2. Exploratory data analysis
Descriptive statistics, hypothesis tests (ANOVA, chi-square, normality,
association with the target) and 10 publication-quality figures, summarised in
`outputs/reports/eda_summary_report.md`.

### 3. Predictive modelling — patient deterioration
Predicts the 12-month deterioration flag. The raw complication label is excluded to
prevent leakage. Best test-set results:

| Model | Accuracy | Precision | Recall | F1 | ROC-AUC | PR-AUC |
|---|---|---|---|---|---|---|
| **Logistic Regression** | 0.795 | 0.554 | 0.815 | **0.659** | **0.875** | 0.745 |
| Random Forest | 0.803 | 0.573 | 0.753 | 0.651 | 0.859 | 0.713 |
| Gradient Boosting | 0.844 | 0.722 | 0.582 | 0.645 | 0.865 | 0.727 |
| XGBoost | 0.789 | 0.546 | 0.783 | 0.644 | 0.868 | 0.738 |

Artefacts: metrics CSV, confusion matrices, ROC/PR curves, feature-importance plots,
`model_registry.json`, and a calibrated `DeteriorationPredictor` with Low/Medium/High
risk bands.

### 4. Outpatient load forecasting & resource planning
A Prophet+SARIMA ensemble forecasts 12 weeks of demand (~770 visits/week on average),
which is converted into staffing needs, cost-optimised with a linear program, and
presented in an HTML dashboard.

Artefacts:
- `outputs/reports/load_forecast.csv` — weekly forecast, total + per clinic
- `outputs/reports/resource_schedule.csv` — staffing & utilisation, high-load flags
- `outputs/reports/schedule_optimization.csv` — cost-optimal staffing (PuLP/CBC)
- `outputs/reports/forecast_dashboard.html` — interactive dashboard
- `outputs/reports/outpatient_forecast_report.md` — narrative resource plan

## Data dictionary (feature store, selected columns)

| Column | Type | Description |
|---|---|---|
| `patient_id` | str | Unique patient identifier |
| `age` | int | Age in years (18–95) |
| `sex` | cat | M / F |
| `bmi` | float | Body mass index |
| `hba1c` | float | Glycated haemoglobin (%) |
| `fasting_glucose` | float | Fasting glucose (mg/dL) |
| `systolic_bp` / `diastolic_bp` | int | Blood pressure (mmHg) |
| `ldl` / `hdl` / `triglycerides` | float | Lipid panel (mg/dL) |
| `creatinine` / `egfr` / `urine_acr` | float | Renal panel |
| `years_since_diagnosis` | float | Diabetes duration |
| `comorbidity_index` | float | Weighted comorbidity aggregate |
| `visit_count_12m` | int | Outpatient visits in last 12 months |
| `avg_duration` | float | Mean visit duration (min) |
| `no_show_rate` | float | Fraction of missed appointments |
| `n_urgent` | int | Urgent visits in last 12 months |
| `flag_*` | int | NLP keyword flags (renal, cardiac, referral, …) |
| `complication` | cat | Complication class (excluded from model features) |
| `deteriorated_12m` | int | **Target** — deterioration within 12 months |

A complete, auto-profiled catalogue of every dataset is in `docs/data_catalog.json`.

## Configuration

All tunables live in `config/config.yaml`: paths, random seed, data-generation
volumes, ETL thresholds, model hyper-parameter grids, forecasting horizon/weights,
and scheduling productivity ratios and costs. Nothing needs to be hard-coded or
passed on the command line beyond `--pipeline`.
