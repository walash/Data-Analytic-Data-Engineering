## Content

𝑳𝒆𝒕'𝒔 𝒕𝒂𝒍𝒌 𝒂𝒃𝒐𝒖𝒕 𝑺𝑸𝑳 𝒒𝒖𝒆𝒓𝒚 𝒐𝒑𝒕𝒊𝒎𝒊𝒛𝒂𝒕𝒊𝒐𝒏:

1. 𝑼𝒔𝒆 𝑰𝑵 𝑷𝒓𝒆𝒅𝒊𝒄𝒂𝒕𝒆 𝑾𝒉𝒆𝒏 𝑸𝒖𝒆𝒓𝒚𝒊𝒏𝒈 𝒂𝒏 𝑰𝒏𝒅𝒆𝒙𝒆𝒅 𝑪𝒐𝒍𝒖𝒎𝒏
  - For indexed retrieval, the IN-list predicate can be used, and the optimizer can sort the IN-list to match the index’s sort order for more effective retrieval. Note that the IN-list should only contain constants, such as outer references.

2. 𝑼𝒔𝒆 𝑬𝑿𝑰𝑺𝑻𝑺 𝑹𝒂𝒕𝒉𝒆𝒓 𝑻𝒉𝒂𝒏 𝑫𝑰𝑺𝑻𝑰𝑵𝑪𝑻 𝒊𝒏 𝑶𝒏𝒆-𝒕𝒐-𝑴𝒂𝒏𝒚 𝑱𝒐𝒊𝒏𝒔
  - DISTINCT creates groups in a query, which requires significant computational power. Using a subquery with the EXISTS keyword avoids returning an entire table and is more efficient.

3. 𝑨𝒗𝒐𝒊𝒅 𝑨𝒈𝒈𝒓𝒆𝒈𝒂𝒕𝒆 𝑭𝒖𝒏𝒄𝒕𝒊𝒐𝒏𝒔 𝒐𝒏 𝒕𝒉𝒆 𝑹𝒊𝒈𝒉𝒕 𝑺𝒊𝒅𝒆 𝒐𝒇 𝑶𝒑𝒆𝒓𝒂𝒕𝒐𝒓𝒔
  - Placing aggregate functions on the right side of an operator can hinder SQL query performance. Instead, optimize your queries by avoiding this practice.

4. 𝑼𝒔𝒆 𝑾𝑯𝑬𝑹𝑬 𝑰𝒏𝒔𝒕𝒆𝒂𝒅 𝒐𝒇 𝑯𝑨𝑽𝑰𝑵𝑮 𝒕𝒐 𝑫𝒆𝒇𝒊𝒏𝒆 𝑭𝒊𝒍𝒕𝒆𝒓𝒔
  - Optimized SQL queries retrieve only the necessary records. WHERE statements are more effective for filtering because they are processed before HAVING statements in the SQL Order of Operations.

5. 𝑨𝒗𝒐𝒊𝒅 𝑼𝒏𝒏𝒆𝒄𝒆𝒔𝒔𝒂𝒓𝒚 𝑫𝑰𝑺𝑻𝑰𝑵𝑪𝑻 𝑪𝒐𝒏𝒅𝒊𝒕𝒊𝒐𝒏𝒔
  - The DISTINCT statement removes duplicates by creating groups, which requires considerable computational power. Instead, choose more fields to produce distinct results rather than using SELECT DISTINCT.

6. 𝑼𝒔𝒆 𝑱𝑶𝑰𝑵 𝑰𝒏𝒔𝒕𝒆𝒂𝒅 𝒐𝒇 𝒂 𝑺𝒖𝒃𝒒𝒖𝒆𝒓𝒚
  - JOINs execute faster than subqueries. Unlike subqueries, which execute all queries and load all data for processing, JOINs allow RDBMS to create an efficient execution plan that predicts which data should be loaded, saving time.

7. 𝑼𝒔𝒆 𝑼𝑵𝑰𝑶𝑵 𝑨𝑳𝑳 𝑰𝒏𝒔𝒕𝒆𝒂𝒅 𝒐𝒇 𝑼𝑵𝑰𝑶𝑵 𝑾𝒉𝒆𝒓𝒆𝒗𝒆𝒓 𝑷𝒐𝒔𝒔𝒊𝒃𝒍𝒆
  - UNION ALL is faster than UNION because it does not remove duplicates, even if they exist. UNION ALL simply displays the data with duplicates.

8. 𝑨𝒗𝒐𝒊𝒅 𝑼𝒔𝒊𝒏𝒈 𝑶𝑹 𝒊𝒏 𝑱𝒐𝒊𝒏 𝑸𝒖𝒆𝒓𝒊𝒆𝒔
  - Using OR in join queries can significantly slow down query performance.
